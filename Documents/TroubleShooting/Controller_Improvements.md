# PCC 화면 및 로직 개선 제안  

목적  
- PCC(Pribit Connect Controller) UI/UX와 내부 로직에서 발견된 개선사항을 정리하여 우선순위별로 개선 작업을 계획/할당하기 위함.

요약(핵심 개선 영역)  
- UI: 네비게이션, 대시보드 가독성, 폼/입력 UX, 오류/상태 메시지, 다국어(한글) 정합성  
- 로직: 인증/세션 처리, DB 초기화/마이그레이션 안정성, 재시도 및 타임아웃 정책, 헬스체크/모니터링 통합  
- 성능/운영: 리소스 제한, 로그/감사 추적, 컨테이너/서비스 오케스트레이션 고려  
- 보안: 비밀번호/민감정보 취급, 권한 최소화, 입력 검증

필요(필수) 기능 
- 3rd Party 인증&연동 기능 
  - ex) SAML 인증 & 사용자 동기화  
- PCC 작업 스케쥴러 직접 설정
  - PCC 에서 수행되는 스케쥴러 작업을 컨트롤 할 수 있는 기능
  - ex) 동기화 스케쥴러 작업, 휴면 계정 처리 작업, 정책 백업 등등 .. 
- Gateway Domain 주소 입력 가능
  - 현재 IP만 입력 할 수 있음  
- DB 분리 가능 해야 함
- 인증 로그가 남지 않음
  - Internal DB 로 로그인 했는지 또는, AD로 인증 했는지 로그에 남지 않음




## 우선순위별 개선 항목
`아직 정리 되지 않음`


1. Critical (P0)
- DB 초기화/마이그레이션 안전성
  - 문제: init SQL에서 변수/중복 생성으로 컨테이너 기동 실패(예: CREATE DATABASE 충돌)  
  - 개선안: init 스크립트는 idempotent 하게 변경 (IF NOT EXISTS 사용), 변수 치환은 컨테이너 런타임에서 템플릿으로 처리
  - 수용기준: 동일 init.sql을 여러 번 실행해도 오류 없이 동작

- 인증/비밀번호 처리
  - 문제: authenticate.properties 생성/암호화 흐름 불투명, 비밀번호 하드코딩 가능성  
  - 개선안: 비밀번호/민감정보는 환경변수 또는 시크릿 관리(예: Vault/Kubernetes Secret)로 처리, 생성 과정 로깅 제한
  - 수용기준: authenticate.properties 생성 시 평문 노출 없음, 복호화 권한 로그 검증 가능

2. High (P1)
- 서비스 헬스체크/순차 기동
  - 문제: 서비스 의존성(예: DB 기동 대기) 처리 미비  
  - 개선안: systemd 유닛 또는 Docker Healthcheck로 의존성 명시 및 재시도 정책 추가
  - 수용기준: 컨트롤러 서비스가 DB/Redis 준비 후 기동

- 에러/상태 메시지 개선
  - 문제: 사용자에게 전달되는 메시지 불명확(로그 확인 필요)  
  - 개선안: 사용자용 요약 + 내부 로그 상세 구조 적용(코드/요약/조치 안내)
  - 수용기준: UI에서 1문장 요약 + "자세히 보기"로 로그 링크 제공

3. Medium (P2)
- UI: 대시보드 및 모니터링 가독성
  - 개선안: 핵심 KPI 위젯(서비스 상태, 연결 수, 에러율), 실시간 알람 배지, 필터/검색 개선
  - 수용기준: 관리자 1분 내 시스템 상태 파악 가능

- 사용자/그룹 관리 UX
  - 문제: 대량 사용자 등록 및 동기화 오류 처리 미비  
  - 개선안: 배치 결과 리포트, 실패 항목 재처리 기능 추가
  - 수용기준: 일괄 등록 실패 시 실패 레코드 CSV 제공

4. Low (P3)
- 접근성/다국어 일관성
  - 개선안: 한글/영문 리소스 분리·검증, 날짜/시간 포맷 일관화
- 문서화 강화
  - 개선안: 설치/마이그레이션/복구 절차를 단계별 체크리스트로 문서화

세부 기술적 제안(로직 관점)
- Init SQL 템플릿 처리
  - 템플릿 파일: init.sql.tpl (플레이스홀더: {{MYSQL_ROOT_PASSWORD}}, {{PRIBIT_USER}} 등)
  - 런처 스크립트에서 envsubst 또는 간단한 sed 치환으로 실제 init.sql 생성
- 서비스 기동 스크립트
  - systemd unit에 Requires= 및 After= 로 의존성 명시
  - Docker Compose 사용 시 depends_on + healthcheck 설정
- 재시도/타임아웃 정책
  - DB 연결 시 exponential backoff 적용(최대 재시도/총 대기시간 설정)
- 헬스체크
  - HTTP /health, DB 연결 체크, Redis PING 포함
  - Prometheus 메트릭 노출 포인트 마련
- 로그/감사
  - 중요한 이벤트(인증 실패, 설정 변경)를 별도 감사 로그로 분리
  - 로그 포맷: timestamp level component code message

보안 권고
- authenticate.properties 및 기타 민감파일 권한 최소화 (600, 소유자 root 또는 서비스 전용 계정)
- DB 루트 비밀번호/서비스 계정은 시크릿스토어로 관리
- 네트워크: 내부 서비스는 네트워크 분리 및 방화벽 규칙 적용

테스트 및 수용기준(예)
- 배포 자동화 테스트 시나리오: 빈 환경에서 컨테이너 3회 연속 생성/삭제 후 서비스 정상동작 확인  
- 회귀: 주요 기능(로그인, 에이전트 배포, 정책 적용) 자동화 테스트 통과

권장 작업 흐름(단계)
1. 긴급(P0) 항목 개선 — 1 sprint
2. 헬스체크/기동 로직 개선 — 1 sprint
3. UI/UX 개선(대시보드, 폼) — 2 sprint
4. 문서화/테스트 보강 — 병행

담당자(예시)
- Backend: DB/마이그레이션/헬스체크 — 팀 A
- DevOps: 컨테이너/오케스트레이션/시크릿 — 팀 B
- Frontend: Dashboard/UI/UX — 팀 C
- QA: 회귀·자동화 시나리오 — 팀 D

다음 단계
- 각 항목에 대해 담당자/기간/리스크 기재한 개선 계획서 작성
- 우선순위별 프로토타입 및 검증(POC)
- 변경사항 릴리즈 체크리스트 생성
