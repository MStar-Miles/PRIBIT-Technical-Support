## 장애 대응 프로세스

### 1. **장애 인지**    
- 사용자, 고객, 내부 직원 등으로부터 접수된 장애 신고를 확인  
- 장애 인지 후 즉시 관련 담당자에게 상황 공유  
- 장애 발생 시 담당자 또는 모니터링 시스템에서 장애를 인지  
- 장애 발생 시간, 증상, 영향 범위, 관련 시스템 및 서비스 기록  
- 장애 발생 시점의 주요 이벤트(로그, 알림, 경보 등) 수집  
- 장애 발생 전후의 시스템 상태 및 네트워크 상태 파악  
- 장애가 서비스에 미치는 영향(사용 불가, 성능 저하, 데이터 손실 등) 평가  

### 2. **초기 대응**  
- 장애 유형 및 심각도 판단  
- 관련 담당자 및 팀에 즉시 통보  
- 임시 조치(서비스 재시작, 네트워크 점검 등)  

### 3. **원인 분석**
- 로그 및 시스템 상태 확인
- 최근 변경 사항 및 이슈 조사
- 필요 시 외부 지원 요청

### 4. **문제 해결**
- 원인에 따른 해결 방안 적용
- 서비스 정상화 확인

### 5. **사후 조치 및 보고**
- 장애 원인 및 처리 내역 문서화  
- 재발 방지 대책 수립  
- 장애 보고서 작성 및 공유

## 장애 대응 메일 샘플

```
안녕하십니까 프라이빗테크놀로지 OOO 담당자입니다.

먼저, 사용에 불편을 드려 죄송합니다. 

OOO(고객사)의 특정 사용자PC에서 발생되고있는 "에이전트 실행 시 Hang 발생" 이슈에 관련하여 공유드립니다. 

1. 이슈 범위  
- 특정 PC에서만 발생 / Controller Server 관련 장애   

2. 증상 및 이슈 내용  
- 에이전트 실행 시 Hang이 발생하며 비활성화 상태(UI 불투명 처리됨)가 되고, 사용할 수 없는 상태  

3. 영향도 
- 에이전트가 비활성화(UI 불투명 처리)되어 정상적으로 사용할 수 없음   

4. 조치 내용 
    4-1) 1차 원격 확인 
    - 이벤트뷰어 확인 결과 PRIBIT Connect.exe 실행 시 OS내 시스템 라이브러리 접근을 위해 Kernelbase.dll 파일을 호출하며 메모리 엑세스 위반 오류가 발생됨을 확인  
    
    4-2) 추정 원인 별 조치 방안
    (1) OS의 Kernelbase.dll 파일 손상 추정  
        - Kernelbase.dll 파일 교체 시도  
        - 시스템 파일 복구 시도  
    (2) PRIBIT Connect.exe가 Kernelbase.dll 호출 시 메모리 엑세스 위반 오류가 발생됨이 확인되어 이를 근거로 허용되지 않은 메모리 영역에 접근을 시도하여 발생된것으로 추정
        - 윈도우 시스템 DEP 기능에 PRIBIT Connect.exe 예외 추가 후 실행 시도
        - 프로그램에 대한 관리자 권한 확인 및 관리자 권한 실행 시도
    (3) Visual C++ Redistributable 
        - 재배포 패키지 버전 확인 및 재설치 시도

    4-3) 2차 원격 예정 
    - 2025. 08. 30 13:00 원격 지원으로 설정 변경 조치 예정 

5. 사후 진행 
- 동일 이슈 재발 방지를 위해 제품 개선 예정  
- 릴리즈 2.6.4.x (11월 배포 예정) 

만약 상기 조치 사항으로 조치가 되지 않을 시 연구소에서도 현재 해당 이슈를 확인하고 있는 중이므로 자사 연구소를 통해 추가 지원할 수 있도록 하겠습니다.

사용에 불편을 드려 죄송합니다.

감사합니다.

```
